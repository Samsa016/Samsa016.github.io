# Видеодемки кейсов

Демка на портфолио — не скринкаст и не туториал. Это **одно доказательство** того,
что продукт работает. Зритель смотрит без звука, по пути к следующему кейсу, и решает
за первые 2 секунды, стоит ли кликать.

## 0. Критерий приёмки (проверяй первым)

Выключи звук, посмотри 8 секунд, задай себе вопрос: **что этот продукт делает?**
Не смог ответить — ролик переснимается, а не «допиливается монтажом».

## 1. Бюджеты (жёсткие)

| Параметр | Значение |
|---|---|
| Длительность | 8–12 с, петля без заметного стыка |
| Разрешение | 1280×720 (для вертикальных/мобильных кейсов — 720×1280) |
| Вес webm | ≤ 1.2 МБ |
| Вес mp4 | ≤ 1.6 МБ |
| Постер | ≤ 60 КБ, jpg q78 |
| Звук | вырезается полностью (`-an`) |
| FPS | 30, для терминальных прогонов достаточно 24 |

Превышение бюджета — сначала режем длительность и лишние движения, только потом
понижаем битрейт. Мыло хуже, чем короткий ролик.

## 2. Сценарий: три такта

Каждая демка строится одинаково:

1. **Такт 1 (0–2 с) — узнавание.** Сразу главный экран продукта, крупно. Никаких
   заставок, логотипов, пустых страниц и курсора, ищущего кнопку.
2. **Такт 2 (2–7 с) — действие.** Одно осмысленное действие: заявка ушла, фильтр
   применился, агент кликнул сам, бот ответил. Одно. Не тур по интерфейсу.
3. **Такт 3 (7–10 с) — результат.** Видимое последствие действия: новая строка,
   ответ, изменившееся число. Кадр замирает на результате — это же постер.

## 3. Что убивает демку

- Курсор, который мечется и ищет элемент. Двигай мышь по прямой, с паузой перед кликом.
- Модалки cookie, дев-баннеры Next.js, вкладки браузера, панель закладок, часы ОС.
- Пустые состояния и «нет данных». Сначала засей демо-данные.
- Скролл ради скролла.
- Текст мельче 14px в исходном разрешении — на превью он превратится в кашу.
- Реальные персональные данные. Только синтетика. Для клиентских кейсов — обязательно.

## 4. Веб-кейсы: запись скриптом

`scripts/record-demos.mjs` — Playwright пишет видео, ffmpeg режет и жмёт.
Сценарий каждого кейса лежит в том же файле рядом со слагом.

```bash
pnpm demo:record <slug>     # запись
pnpm demo:encode <slug>     # webm + mp4 + постер + доминанта цвета
```

Правила скрипта: `viewport 1280x720`, `deviceScaleFactor 2`, курсор рисуется
явным оверлеем (Playwright не пишет системный), между действиями `waitForTimeout`
не меньше 400 мс — иначе движение читается как дёрганое.

## 5. Терминальные и CLI-кейсы

Пишутся как реальный прогон: `asciinema` или прямая запись окна через
`ffmpeg -f x11grab`. Шрифт крупный (16–18pt), тема тёмная в тон сайту, окно
без заголовка и панелей. Прогон должен быть настоящим — подделанный вывод
видно по таймингам.

## 6. Что снимает владелец сам

Telegram-боты, мобильные приложения и всё, где нужен реальный аккаунт.
Для каждого такого кейса пишем покадровый сценарий: что открыть, что нажать,
сколько секунд держать, чем закончить. Запись экрана телефона — вертикально,
без шторки уведомлений, яркость на максимум.

## 7. Кодирование

```bash
# webm (основной)
ffmpeg -i raw.mp4 -an -c:v libsvtav1 -crf 38 -preset 6 -vf "scale=1280:-2,fps=30" out.webm
# mp4 (Safari fallback)
ffmpeg -i raw.mp4 -an -c:v libx264 -crf 26 -preset slow -profile:v high -pix_fmt yuv420p \
  -movflags +faststart -vf "scale=1280:-2,fps=30" out.mp4
# постер — последний кадр такта 3
ffmpeg -i out.mp4 -ss <t> -frames:v 1 -q:v 6 poster.jpg
```

Постер — это кадр результата, а не первый кадр. Пока видео не загрузилось,
зритель должен видеть готовый продукт, а не пустую форму.

## 8. Перед подстановкой на сайт

- [ ] Уложился в бюджеты раздела 1.
- [ ] Петля не дёргается на стыке.
- [ ] В кадре нет ПД, реальных клиентов, дев-баннеров и лишнего хрома браузера.
- [ ] Постер — кадр результата, вес в бюджете.
- [ ] Доминанта цвета посчитана и записана в `lib/content/cases.ts`.
